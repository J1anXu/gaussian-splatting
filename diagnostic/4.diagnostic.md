# 剩余差距分析 (Adam 动量修复后)

## 修复效果确认

Adam 动量修复生效了:
- **Prune**: ours 从 ~4000/step 降到 ~20-60/step, 与 vanilla ~20-80/step 基本一致
- **Opacity 分布**: 两边 q01~q90 非常接近
- **exp_avg_norm**: 现在 ours 有正常值, 不再是 None

## 根因: 每步梯度一致性偏低 ~10%

从 iter 100 开始, ours 的 per-view gradient 就持续低于 vanilla:

| Iter | Ours grad_mean | Vanilla grad_mean | 比值 |
|------|---------------|------------------|------|
| 100 | 0.00005829 | 0.00006204 | 0.94 |
| 200 | 0.00009082 | 0.00009319 | 0.97 |
| 300 | 0.00006067 | 0.00006804 | 0.89 |
| 400 | 0.00009193 | 0.00010844 | 0.85 |
| 500 | 0.00011762 | 0.00013068 | 0.90 |
| 600 | 0.00009266 | 0.00010769 | 0.86 |

**ours 梯度一致性低 5-15%, 导致每步超过阈值 0.0002 的点更少。**

## 梯度偏低的影响

在 iter 600 (两边基数相同 = 54275):
- Ours: 超过阈值的点 = clone(1312) + split(2229) = **3541**
- Vanilla: 超过阈值的点 = clone(1734) + split(2223) = **3957**
- **ours 少 10.5%**, 之后差距通过复利效应逐步放大

## 可能原因

1. **Block-level 渲染产生不同梯度**: 即使单 block, submodel pipeline 的 loss 计算路径与 vanilla 不同
2. **不同 camera 采样顺序**: random seed 不同导致每步看到的视角不同 (但比值应该围绕 1.0 波动, 而不是一致偏低)
3. **CPU vs GPU 计算数值差异**: packed_sparse_adam 在 CPU 上, vanilla 在 GPU 上, 浮点精度差异可能导致参数更新略有不同, 进而影响下一步的梯度

## 建议

### 方案 A: 恢复梯度阈值补偿
将 `DENSIFY_GRAD_SCALE` 设回 ~0.85-0.90 (而非之前的 0.7), 补偿梯度偏低:
```python
DENSIFY_GRAD_SCALE = 0.85  # 实际阈值 = 0.0002 * 0.85 = 0.00017
```

### 方案 B: 排查 loss 计算差异
对比两边的 loss 值:
- ours 是否对子 block 单独计算 loss? 如果是, loss scale 可能不同, 导致梯度偏小
- 检查 loss 的 reduction 方式 (mean vs sum)

### 方案 C: 统一随机种子
确保两边使用相同的 camera 采样顺序, 排除随机性的影响
