# P0 Opacity 诊断报告

> 数据来源: bicycle 场景, ours (nurips26) vs vanilla3DGS
> 分析时间: 2026-03-25

---

## 1. 关键发现: Ours 的 Adam optimizer state 为 None

**所有迭代中, ours 的 opacity optimizer state 始终为:**
```
exp_avg_norm=None  exp_avg_sq_norm=None
```

**而 vanilla 始终有正常的 Adam state:**
```
exp_avg_norm=0.00016  exp_avg_sq_norm=2.7e-08  (iter 2000 典型值)
```

这意味着 **ours 的 opacity 没有通过标准 Adam optimizer 更新**,
很可能是 `packed_sparse_adam_step` 自定义优化器路径跳过了或错误处理了 opacity 的 Adam 动量。

## 4. 根因分析

### 4.1 最可能的原因: `packed_sparse_adam_step` 对 opacity 处理有 bug

证据:
- `exp_avg_norm=None` 说明标准 Adam 的动量状态没有被填充
- 这意味着 opacity 要么没被优化, 要么通过一个不同的路径优化
- 如果 opacity 的 Adam 一阶动量 (exp_avg) 缺失, 优化器就没有"记忆", 每步的梯度直接作用, 没有平滑, 导致部分点 opacity 快速衰减

### 4.2 为什么 vanilla 的低 opacity 点能被"拉回来"

Vanilla 有正常的 Adam state:
- `exp_avg` 提供梯度平滑, 防止单步大幅波动
- `exp_avg_sq` 提供自适应学习率, 限制更新幅度
- 这两个动量让 opacity 的训练更稳定, 低 opacity 点有机会回升

Ours 缺少这些动量:
- 没有平滑 → opacity 可能被单步大梯度直接拉到极低值
- 没有自适应 lr → 所有点用相同的更新步长, 某些点过度更新

## 5. 排查建议

### 5.1 立即检查: packed_sparse_adam 是否处理了 opacity

```python
# 在 packed_sparse_adam_step 中加日志, 确认:
# 1. opacity 列是否被包含在 packed buffer 中
# 2. opacity 的梯度是否被正确传入
# 3. Adam 的 exp_avg / exp_avg_sq 是否在 packed buffer 中维护
```

### 5.2 对比检查: opacity 的梯度流

在 `loss.backward()` 后, 打印:
```python
print(f"opacity grad norm: {self._opacity.grad.norm().item()}")
print(f"opacity grad nonzero: {(self._opacity.grad != 0).sum().item()}")
```

确认 opacity 是否收到了梯度, 以及梯度是否被正确传递到优化器。

### 5.3 临时修复方案

如果确认是 packed_sparse_adam 的问题, 可以让 opacity 走标准 Adam 而非 packed 路径:
- 将 opacity 从 packed buffer 中拆出来
- 单独用 `torch.optim.Adam` 更新 opacity
