# Densify 点数增长异常诊断报告

> 数据来源: bicycle 场景, ours (nurips26) vs vanilla3DGS
> 分析时间: 2026-03-25
> 数据范围: iter 0 ~ 6000 (ours) / iter 0 ~ 8700 (vanilla)

---

| 600 (首次densify) | 54,275 → 58,234 | 54,275 → 57,805 | -1% |

**结论: 差距从 iter 600 就开始出现, 逐步累积放大。**

---

## 2. 根因 #1: Prune 率差异巨大 (最大嫌疑)

### 2.1 Opacity Prune 对比 (iter 3000 opacity reset 之前)

| Iter | Vanilla prune (opa) | Ours prune (opa) | 倍数差 |
|------|---------------------|------------------|--------|
| 700 | 6 | 89 | 15x |
| 800 | 4 | 238 | 60x |
| 1000 | 6 | 342 | 57x |
| 1500 | 11 | 1,875 | 170x |
| 2000 | 49 | 4,065 | **83x** |
| 2500 | 87 | 5,716 | **66x** |
| 2900 | 145 | 7,000 | **48x** |

**Ours 的 opacity prune 是 vanilla 的 50-170 倍！**

这意味着 ours 中大量 Gaussian 点的 opacity 降到了 0.005 以下被删除,
而 vanilla 中几乎不发生这种情况。

### 2.2 这不是梯度问题

两边的梯度分布几乎相同:

| Iter | 指标 | Vanilla | Ours |
|------|------|---------|------|
| 600 | grad_mean | 0.000072 | 0.000073 |
| 600 | pct90 | 0.000156 | 0.000144 |
| 600 | pct99 | 0.000679 | 0.000712 |
| 2000 | grad_mean | 0.000097 | 0.000093 |
| 2000 | pct90 | 0.000214 | 0.000195 |
| 2000 | pct99 | 0.000530 | 0.000443 |

**梯度分布近乎一致, 问题不在梯度累积, 而在 opacity 训练。**

### 2.3 可能原因

1. **CPU sparse adam 实现问题**: opacity 的优化器状态在 CPU 上可能行为不同
2. **packed buffer 梯度回传**: opacity 的梯度在 pack/unpack 过程中可能丢失或衰减
3. **optimizer learning rate**: opacity 的 lr schedule 在 ours 中可能不同
4. **梯度裁剪或归一化**: 如果 ours 对梯度做了额外处理, 可能影响 opacity 收敛

---

## 3. 根因 #2: blk0 的 denom 偏低

分裂成两个 block 后 (iter 3000+):

| Block | denom_mean | 对比 |
|-------|-----------|------|
| blk0 | ~13 | 偏低 |
| blk1 | ~21-23 | 正常 |
| Vanilla | ~22-25 | 正常 |

**blk0 每个点的平均观测次数只有 vanilla 的一半。**

可能原因: blk0 覆盖的空间区域在训练视角中被采样的频率较低,
或者 frustum culling 把 blk0 的点过度剔除了。

## 5. 恶性循环图解

```
初始差距 (iter 600: -1%)
        │
        ▼
  ours opacity prune 多 50-170x
        │
        ▼
  基数变小 → 每步新增绝对数减少
        │
        ▼
  与 vanilla 差距进一步拉大
        │
        ▼
  反复累积 → iter 6000 差距达 40%
```

---

## 6. 排查建议 (优先级从高到低)

### P0: 检查 opacity 训练流程
- 对比两边 opacity 的 learning rate 和 schedule
- 检查 CPU sparse adam 是否正确更新 opacity 参数
- 在 `densify_and_prune` 前打印 opacity 分布:
  `torch.quantile(self.get_opacity.squeeze(), torch.tensor([0.01, 0.05, 0.1, 0.5]))`
- 对比两边 opacity 分布是否一致

### P1: 检查 packed buffer 中 opacity 梯度
- 在 adam step 前后打印 opacity 梯度的 norm
- 确认 pack/unpack 没有丢失 opacity 的梯度信息

### P2: 检查 blk0 可见性
- 打印 blk0 和 blk1 的空间范围 (xyz min/max)
- 检查 frustum culling 对 blk0 是否过度保守
