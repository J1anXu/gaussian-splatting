# Densify 点数增长异常：最终诊断总结

## 已修复的问题

### Bug 1: Packed Adam 动量每次 Densify 被归零（已修复）
- **现象**: prune 数量是 vanilla 的 50-170 倍（ours ~4000/step vs vanilla ~50/step）
- **根因**: `_init_packed_adam_state()` 在每次 `pack_to_buffer()` 时将所有 Adam 动量归零，而 `optimizer.state` 始终为空（packed 路径不调 `optimizer.step()`），导致 `cat_tensors_to_optimizer` 无法保留动量
- **修复**: 新增 `_sync_packed_adam_to_optimizer_state()`，densify 前同步动量；修改 `_init_packed_adam_state()` 从 `optimizer.state` 回填
- **效果**: prune 降到 ~20-60/step，与 vanilla 一致

### Bug 2: SSIM 实现不同（已修复）
- **现象**: 同一 camera 同一 iter，梯度低 10-30%
- **根因**: ours 用 `diff_gaussian_rasterization_wenqi_tam._C.fusedssim`，vanilla 用 `fused_ssim_cuda.fusedssim`，两个不同的 CUDA kernel 产生不同 SSIM 值和梯度
- **修复**: ours 改用 vanilla 的 `fused_ssim`
- **效果**: 单 block 阶段点数差距从 ~20% 缩小到 ~1-4%

## 剩余差距：Block Split 后的固有影响

iter 2400 左右 block split 后，差距再次拉大，原因：

### 1. prefix_T 梯度缩放
```
iter=2600 blk=0: prefix_T_mean=0.3407 → 梯度被缩放到 34%
iter=2600 blk=1: prefix_T_mean=0.7355 → 梯度被缩放到 74%
```
每个 block 的梯度被其他 block 的透射率缩放，导致整体梯度偏低。

### 2. Denom 降低
- blk0 denom_mean ≈ 10-17（较少被观测到）
- blk1 denom_mean ≈ 27-30
- Vanilla denom_mean ≈ 24

部分 block 因空间位置关系，被相机观测的频率较低。

### 3. 这些不是 Bug
这是 block 分割架构的固有特性：
- 每个 block 独立 backward，跨 block 梯度交互丢失
- 透射率前缀 detached，缩放了梯度幅度
- 空间分块导致观测不均匀

## 建议

### 对于 Block Split 后的差距
考虑仅在 split 后启用 `DENSIFY_GRAD_SCALE` 补偿：
```python
# pipeline_grad_sync.py
if len(submodel_list) > 1:
    scale = 0.7  # 补偿 prefix_T 缩放
else:
    scale = 1.0  # 单 block 不需要补偿
```
